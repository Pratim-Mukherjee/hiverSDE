# HIVER TAKE HOME ASSIGNMENT:- "AmazonHelp Support Agent" 

This project builds a support agent for AmazonHelp using the real Customer Support on Twitter dataset. The system is intentionally classical, transparent, and auditable: TF-IDF intent classification, retrieval-grounded draft generation, and explicit escalation policy.

A first classical/retrieval-based system on noisy public Twitter support data 

## What this project does

- Reads the real Kaggle TWCS support dataset and reconstructs first-customer-message → brand-reply pairs
- Trains a TF-IDF + logistic-regression intent classifier using the real AmazonHelp corpus
- Retrieves historical brand replies grounded in similar customer messages
- Drafts replies by adapting those historical resolutions rather than inventing new facts
- Applies an explicit escalation policy for risk-heavy intents and safety triggers
- Evaluates the system with leakage checks, confusion matrices, per-intent metrics, bootstrap confidence intervals, and McNemar significance testing
- Includes a human-review workflow so a reviewer can turn the candidate gold set into a genuinely reviewed final evaluation set



## Why the architecture matters

Real customer support data is noisy, messy, multilingual, and full of preserving artifacts such as internal agent sign-offs, short fragments, and real-world typos. In this setting, a transparent pipeline is valuable because it can be debugged and reasoned about.

The pipeline aims to answer three questions clearly:

1. What intent is this customer message expressing?
2. What historical brand reply is closest to the correct resolution path?
3. Should this be auto-handled or escalated to a human?

## Gold set and human review workflow

A real benchmark must be reviewed, not just generated by keyword heuristics. The project is structured so a reviewer can do the final human pass before claiming performance numbers.

### Candidate gold set generation

```bash
python -m src.cli golden
```

This creates a real-data candidate gold set using the processed AmazonHelp corpus.

### Human review pass

```bash
python -m src.cli review
```

This writes a reviewable file:

```text
eval/golden_eval_reviewed.csv
```

It contains the fields:

- thread_id
- customer_text
- brand_text
- suggested_intent
- true_intent
- true_action
- review_notes
- reviewer

Reviewers fill in the human labels and then use that reviewed file as the final ground truth before publication.

### Final evaluation file

Before the final claim is made, reviewers can either:

- overwrite the final benchmark with the reviewed file, or
- copy the reviewed data into the final evaluation file used by the evaluator

## Leakage diagnostics and evaluation rigor

The project includes explicit checks for the most important failure mode in this task: train/eval leakage.

```bash
python scripts/check_leakage.py
```

This reports whether any golden-set customer texts are present in the training corpus. If overlap is above zero, the evaluator is not measuring generalization reliably.

The real diagnostics script is:

```bash
python scripts/full_eval.py
```

It reports:

- intent accuracy
- confusion matrix
- per-intent precision / recall / F1
- bootstrap 95% confidence intervals
- McNemar significance test versus the simple baseline
- reference-based reply similarity against the historical brand response
